# Регрессионный набор тестов

Постоянный набор проверок вместо одноразовых Playwright-скриптов в `/tmp`.
Гоняет **собранный** `dist/index.html` — то есть проверяет именно то, что
реально уедет пользователю, а не исходники по отдельности.

## Как запустить

```bash
bun run build && bun run test
# или одной командой:
bun run verify
```

Занимает около 12 минут (~1460 проверок, реальный headless-браузер на каждую
игру). Можно гонять только часть набора:

```bash
bun test/run-all.js --only=smoke          # только базовый прогон всех игр
bun test/run-all.js --only=persistence    # только черновики/восстановление
bun test/run-all.js --only=home           # только главный экран
bun test/run-all.js --only=export         # только экспорт PNG-отчёта
bun test/run-all.js --only=timer          # только настройка таймера
```

Или через bun-скрипты: `bun run test:smoke`, `bun run test:persistence` и т.д.

⚠️ Не путайте `bun run test` (наш скрипт из package.json) с голым
`bun test` — это отдельный, встроенный test-runner Bun; он по умолчанию
ищет файлы `*.spec.js` и здесь их бы нашёл, но не выполнил (наши файлы
не написаны в формате `bun:test`). `bunfig.toml` в корне репозитория
уводит его от `test/`, чтобы такая попытка падала с явной ошибкой,
а не тихо показывала «0 pass / 0 fail» как будто всё ок.

## Структура

| Файл                      | Что проверяет                                                                                                                                                                                                                                                                                                                                  |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lib.js`                  | Общие хелперы: запуск браузера, открытие страницы (свой контекст, включает тестовый флаг `window.__RETRO_TEST__` — без него `window.__reportData` не создаётся — и кладёт в localStorage команду из 14 человек: в приложении списка имён нет; `{ players: null }` — первый запуск), сборщик отчёта (`Report`)                                                                                                                                                                                                                                                                   |
| `games.js`                | **Главный файл** — для каждой игры описано: как дойти до формы, как её заполнить, как дойти до результатов, как проверить, что результат разумный                                                                                                                                                                                         |
| `smoke.spec.js`           | Каждая игра целиком: открыть → заполнить → результаты → контекст → назад в меню, без ошибок в консоли                                                                                                                                                                                                                                          |
| `home.spec.js`            | Главный экран: фильтры (по отдельности и в комбинации), участники (добавить/удалить/аватар), сворачиваемое описание, случайная игра                                                                                                                                                                                                            |
| `persistence.spec.js`     | Черновики: сохранение, **двойная перезагрузка без восстановления** (тот самый race condition, который раньше портил данные молча), восстановление, отмена, что баннер не показывается на непройденной игре                                                                                                                                     |
| `export.spec.js`          | Экспорт результатов в PNG-отчёт для всех игр — игра регистрирует данные отчёта (подзаголовок, участники, пояснение), кнопка «Сохранить картинку» скачивает настоящий PNG шириной 1080px@2x с именем «Название*игры*ДД.ММ.ГГГГ.png», файл не пустой, служебный узел за кадром убирается, кнопка снова доступна, старой печатной разметки нет |
| `swap.spec.js`            | Точечный обмен местами (клик на двух участниках) — для пар (Ультиматум) и для групп (Эффект владения): подсветка выбора, обмен между разными парами/группами, отмена повторным кликом, no-op при обмене внутри одной группы, размеры групп не меняются                                                                                         |
| `copy.spec.js`            | Спойлер + копирование в буфер обмена — оба текста фрейминга скрыты по умолчанию и раскрываются независимо, копирование работает без раскрытия (для приватной отправки в чат), содержимое буфера обмена совпадает с нужным текстом; кнопка копирования в Барнуме                                                                                |
| `trio.spec.js`            | Трио вместо наблюдателя при нечётном числе участников (Ультиматум, Дилемма заключённого) — 7 карточек вместо 6, из них 3 с меткой трио, каждый участник трио фигурирует ровно дважды (по разу с каждой стороны), оба раунда и таблица результатов включают все 7 матчей; контроль — при чётном числе трио не формируется                       |
| `custom-question.spec.js` | Свои вопросы вместо стандартных в играх-викторинах (Мудрость толпы, Калибровка, Ложный консенсус) — дефолтный сценарий не сломан, кастомный текст/ответ/единица доходят до формы, результатов и PNG-отчёта, частичное заполнение отклоняется с понятным сообщением, кнопка «Вернуть стандартный» действительно возвращает исходный вопрос      |
| `exit-dialog.spec.js`     | Подтверждение выхода — настоящий `<dialog>`: × открывает модальное окно (top layer), фокус на «Остаться», «Остаться» / Escape / клик по подложке остаются в игре (черновик цел), «Выйти» возвращает на карту, элемент удаляется из DOM                                                                                                         |
| `timer.spec.js`           | Настраиваемая длительность таймера: шаги − / +, ввод «1:30» или «45», отказ от мусора, «вернуть 0:20» к значению по умолчанию, границы (мин. 0:05); в «Эвристике доступности» у каждого вопроса своя длительность и они не влияют друг на друга; во время отсчёта длительность не редактируется; во «Фрейминге» то же для одного таймера       |
| `chart-tip.spec.js`       | Всплывающая подсказка при наведении на точку графика (Эффект якоря, Мудрость толпы, Игра диктатора) — показывает имя и значение(я), скрывается при уходе курсора, для Диктатора корректно различает раунд 1 и раунд 2 у одного и того же человека                                                                                              |
| `map-layout.spec.js` | Карта на главной: иконки не наезжают друг на друга и не выходят за экран на разных размерах окна, камера и тропа |
| `endowment.spec.js` | Эффект владения: три лота с таймером, распределение групп, ввод цен, результаты, отчёт |
| `framing.spec.js` | Эффект фрейминга: два сценария, спойлеры-тексты для двух групп, таймеры, форма ввода (в т.ч. на 420px), результаты и отчёт |
| `barnum.spec.js` | Эффект Барнума: скрытые вопросы и текст портрета, копирование, оценки, результаты |
| `false-consensus.spec.js` | Ложный консенсус: таймер сбора данных, «да/нет» и прогноз, результаты, свой вопрос |
| `public-goods-calibration.spec.js` | Общественное благо (таймер на раунд, превью раунда 1 во втором) и Калибровка (сложные вопросы, таймер на вопрос) |
| `charts.spec.js` | D3-графики игр из списка `CHARTS` (в т.ч. линейные графики `lines.js` у игр второй партии — метка `.line-dot`): число меток, график помещается в карточку, подпись и `aria-label`, нет `NaN`, высота следует за данными, подсказка при наведении |
| `a11y.spec.js` | Доступность: axe-core (WCAG 2 A/AA + best-practice) на карте и на каждом экране (инструкция, ввод, результаты) всех игр; у каждого поля ввода есть имя; фокус в диалоге выхода и возврат на × по Escape; видимая обводка фокуса |
| `players.spec.js` | Игроки: первый запуск с пустым списком (кода с именами нет, игру не запустить, курсор в поле), добавление (Enter, пробелы, повторы без учёта регистра, пустое, длинное, HTML как текст), переименование (Enter/Escape/занятое имя), «играет сегодня» (игры берут только играющих), удаление, вставка списком, список помнится после перезагрузки, «Удалить всех» с подтверждением, минимум 2 игрока, испорченное хранилище |
| `projector.spec.js` | Экран для показа (все 21 игра — из `games.js`): открытие и связь окон, следование за игрой и выход на карту, вопрос и таймер (идёт, сброс, «Время вышло»), результаты с графиком без прокрутки в окнах 800×600 / 1280×720 / 1920×1080, данные по ходу заполнения (карточка человека появляется с первым числом, счётчик растёт, стёртое пропадает; «Диктатор» раунд 1 и «Общественное благо» — суммы без имён и по возрастанию; пары; вопросы «Доступности» по одному), условие «Диктатора» и его таймер, приветственный экран (команда из окна ведущего в том же порядке и с теми же цветами аватаров, живёт вместе со списком игроков, иконки и заголовок анимированы, строка «в программе» меняется, неподвижен при «уменьшить движение», имена — текстом), таймер на карте раундов (кольцо сидит на иконке игры и едет за ней, красный за 5 секунд, пульс экрана в последние 3 секунды, вспышка по нулю, плашка вместо кольца, без анимации при «уменьшить движение»), график не «мигает» при перерисовке; **приватность** — на проекторе нет текстов групп (Фрейминг), вопросов и портрета (Барнум), шагов для ведущего, имён участников, полей и кнопок (проход по всем играм); перезагрузка любого окна, чужие и вредные сообщения |

## Как добавить новую игру в набор

Новую игру не нужно тестировать отдельным файлом — достаточно добавить один
объект в `games.js`:

```js
{
  id: 'your-game-id',              // совпадает с ключом в persist.js
  name: 'Название с карточки',     // как написано на главном экране
  async toEntryScreen(page) { ... }, // клики от инструкции до формы ввода
  async fill(page, opts) { ... },    // opts.count — если нужно частичное заполнение
  async toResults(page) { ... },     // клики до экрана результатов
  async verifyResults(page) { ... }, // возвращает true/false — разумен ли результат
  async restored(page) { ... },      // необязательно: как увидеть, что черновик восстановлен,
                                     // если он живёт не в полях ввода (лог ставок аукциона,
                                     // недельные заказы пивной игры)
  hasRoles: true,                    // необязательно: у игры есть распределение ролей
}
```

Хелперы `pickInRows(page, rowSelector, pick, count)` (нажать кнопку в каждой строке) и
`fillInputs(page, selector, value, count)` в конце `games.js` покрывают большинство форм.

Наборы `smoke`, `persistence`, `export` и `a11y` автоматически подхватят новую игру
из `games.js` — переписывать их не нужно (остальные наборы — `swap`,
`copy`, `trio`, `custom-question`, `chart-tip`, `charts` — заточены под
конкретные игры и заводятся под новую механику отдельно, если она нужна). График результатов
новой игры — строкой в `CHARTS` в `charts.spec.js`. Число игр нигде не хардкодится: `map-layout`,
`home` и `projector` считают его из `GAMES` (кроме числа игр в категории
«Социальная психология» в `home.spec.js` — при добавлении туда игры поправьте `SOCIAL_GAMES`).

## Safari (WebKit)

Те же наборы можно прогнать в WebKit — движке Safari. Один раз поставьте браузер
(`bunx playwright install webkit`, ~80 МБ), дальше:

```bash
bun run test:webkit                        # проектор + a11y + smoke
BROWSER=webkit bun test/run-all.js --only=projector,charts
```

Наборы с буфером обмена (`framing`, `barnum`, `copy`) в WebKit не запускаются: Playwright не умеет
выдавать ему разрешения `clipboard-*`. В WebKit сейчас падают 6 проверок в других наборах (они одинаково падают и на `main`, к проектору не
относятся; причины не разбирались): имя скачанного PNG у «Ложного консенсуса», «Фрейминга» и «Дилеммы»
не совпадает с ожидаемым, тест скрытия подсказки графика у «Эффекта якоря», и две проверки фокуса в
`a11y` (возврат фокуса на × после Escape и обводка у элемента, на который пришёл Tab).

## Требования

`playwright` — уже используется остальным проектом при разработке; если
запускаете набор отдельно от текущего окружения, поставьте зависимости:

```bash
bun install
bunx playwright install chromium
```

## Визуальные регрессии PNG-отчёта (`test/visual/`)

Отдельный набор на **Playwright Test** (`@playwright/test`) — потому что сравнение
изображений (`toMatchSnapshot`) есть только в его раннере; остальной E2E остаётся на
лёгком `test/run-all.js`. Для каждой игры из `games.js`: довести до результатов теми же
данными, скачать отчёт («Сохранить результаты») и сравнить с эталоном в
`test/visual/__snapshots__/<платформа>/<игра>.png`.

```bash
bun run build
bun run test:visual            # сравнить с эталонами
bun run test:visual:update     # перезаписать эталоны после намеренного изменения
```

- Всё, что меняется от запуска к запуску, зафиксировано: дата на отчёте
  (`page.clock.setFixedTime`), `Math.random` (перемешивание групп/пар — seeded),
  вьюпорт, reduced-motion.
- Отчёт скачивается в 2× (~2000px) и перед сравнением сжимается до 720px по ширине
  (через `sharp`): иначе эталоны весили бы ~20 МБ, а регрессия вёрстки видна и так.
  Проверено вручную: уменьшение заголовка на 6px ловится (`61799 pixels are different`).
- Эталоны **зависят от платформы** (системные шрифты у macOS и Linux рендерятся по-разному),
  поэтому лежат в подпапке `darwin/`. На другой ОС первый запуск без эталонов упадёт —
  запишите их своими `test:visual:update`.
- Diff-картинки при падении — в `test-results/` (в `.gitignore`).
- **Эталоны сейчас есть только для первых 13 игр.** У 8 игр второй партии их нет, а у
  «Дилеммы заключённого» и «Ультиматума» в отчёт добавилась итоговая таблица — перед
  следующим `test:visual` запишите эталоны заново: `bun run test:visual:update`.
