# retro — «5 минут общего развития»

Веб-платформа с мини-экспериментами (экономика/психология решений) для
командных встреч и ретро. Один сценарий на все игры: инструкция без
спойлеров → (распределение ролей, если нужно) → форма → результаты
команды → история эффекта → экспорт в PNG.

## Как работать с проектом

1. Правим только файлы в `src/` (и, если добавляем игру, кладём новый
   `src/games/<id>.js`).
2. Собираем: `bun run build` → обновляется `dist/index.html`.
3. Проверяем: `bun run test` (или `bun run verify`, чтобы собрать
   и прогнать тесты одной командой) — см. `test/README.md`.
   ⚠️ Именно `bun run test`, а не голый `bun test` — это свой
   test-runner Bun, у него другой формат тестов, см. `bunfig.toml`.
4. Отдаём пользователю только `dist/index.html` — это самодостаточный файл,
   открывается двойным кликом, без сервера и сборки на его стороне.

`bun install` сам ставит локальный git-хук `pre-push` (см. `scripts/`),
который перед каждым `git push` собирает проект и гоняет быстрый
smoke-набор (~1 мин, все игры целиком, без остальных наборов) —
чтобы явно сломанная игра не улетела на сервер до полного прогона в CI.
Полный набор (`bun run verify`) при этом всё равно гоняется в CI на
каждый push/PR (`.github/workflows/verify.yml`). Пропустить хук разово:
`git push --no-verify`.

`src/*.js` — настоящие ES-модули ,
поэтому `src/index.html` **больше нельзя** просто открыть двойным кликом —
браузеры блокируют `import` по `file://` (в отличие от классических
`<script src>`, на которых всё держалось раньше). Для живой проверки в
браузере во время разработки: `bun run dev` → http://localhost:5173.
Кроме того, `home.js` и все игры импортируют `lit`
голым bare-специфайером (`import { LitElement } from 'lit'`) — браузер не
может зарезолвить такое сам ни при какой раздаче статики. Поэтому
`scripts/dev-server.js` не просто отдаёт `src/app.js` как есть: запрос на
`/app.js` он на лету прогоняет через `Bun.build()` (тот же бандлер, что и
`build.js`, только без минификации и с inline source map), которая
резолвит `lit` и весь остальной граф импортов в один валидный ES-модуль.
Остальное (`styles.css`, `index.html`, статика) по-прежнему отдаётся как
обычные файлы. `dist/index.html` эта проблема не касается — `build.js`
инлайнит весь собранный бандл как текст в один `<script type="module">`,
без отдельных файловых запросов.

## Общие паттерны (переиспользуются во всех играх)

Каждая игра — Lit-компонент (`LitElement`, `customElements.define('retro-game-<id>', ...)`)
с Shadow DOM: рендер декларативный (`html\`\`` шаблон + реактивные
`static properties`), а не императивная сборка `innerHTML` строк. Общие
модули ниже — то, что осталось переиспользуемым при таком подходе; часть
старого API (императивная генерация HTML + делегированные слушатели)
исчезла вместе с переходом на Lit.

- **`roles.js`** — только чистые функции без DOM: `Roles.makePairs()` /
  `Roles.makeGroups()` случайно делят участников на пары или на 2 группы
  (при нечётном числе участников `makePairs()` формирует трио вместо
  наблюдателя — см. комментарий в файле), `Roles.swapInPairs()` /
  `Roles.swapInGroups()` меняют местами двух участников. Рендер карточек
  пар/групп и клик-для-обмена — в шаблоне каждого игрового компонента
  (реактивное состояние `selectedSwapName`), см. `src/games/ultimatum.js`.
- **`persist.js`** — `Persist.save/load/clear` пишут черновик игры в
  `sessionStorage` (только на вкладку, не навсегда) при каждом изменении
  ответа; `Persist.hasAny()` — предупреждение при закрытии вкладки с
  несохранённым прогрессом. `timeAgo(ts)` — отдельный экспорт для баннера
  восстановления, который каждый компонент рендерит декларативно из
  своего `this.draft` (загруженного в конструкторе через `Persist.load`).
- **`report-export.js`** — экспорт экрана результатов в брендированную
  PNG-картинку (без диалога печати, файл просто скачивается).
  `ReportExport.register(gameId, { subtitle, meta, explanation }, root)`
  вызывается в `_showResults()` игры; `root` — обычно `this.renderRoot`
  (нужен, чтобы найти экран результатов внутри shadow root).
  `ReportExport.download(button)` рисует за кадром отчёт шириной 1080px —
  шапка с 3D-иконкой и акцентным цветом игры, мета-карточка (участники,
  формат, время, дата), КЛОН самого экрана результатов (главная цифра,
  график, карточки, таблица — со стилями приложения) и блок «Что это
  было» — и растеризует его через `html-to-image` в PNG (@2x). Имя файла:
  `Эффект_якоря_10.09.2026.png`. `ReportExport.meta(count, extra)` — данные
  для чипа участников.
- **`charts/` + `ChartController`** — графики результатов (D3): игра
  описывает в `_drawChart(svg, theme)` данные (`logic/chart-data.js`) и
  вызывает `drawSwarm/drawBars/drawScatter/drawIntervals/drawLines`; контроллер
  перерисовывает график после рендера и при смене размера. Высота SVG
  следует за данными.
- **`RoundTimers`** — для игр с таймером на каждый раунд/вопрос/лот:
  `this.timers = new RoundTimers(this, { seconds, count })`,
  `${this.timers.card(i, { runningLabel })}`, `this.timers.reset()` при
  переходе, `resetAll()` при «Начать заново».
- **`content/*.json` + `content.js`** — инструкция, контекст и факты игры
  живут в JSON (см. выше); в шаблоне игры — `${renderSteps(CONTENT.intro.steps)}`,
  `${renderContext(CONTENT.context)}`, `${renderFacts(CONTENT.facts)}`.
- **Правила для игроков — `renderRules(CONTENT.rules, vars)`.** Первый экран каждой
  игры, сразу под заголовком: 2–3 коротких правила и «Ход игры» по шагам (или
  `flowTitle`, например «Цепочка поставок»). Карточка помечена `data-projector="body"`,
  так что зал читает правила сам, а не только слушает ведущего. Шаги `intro.steps`
  по-прежнему — реплики ведущего и на проектор не идут. Правила не должны выдавать,
  что проверяет эксперимент (в «Диктаторе» не сказано, чем будет второй раунд,
  в «Ошибке планирования» — каким будет второе число). У «Диктатора» `items` пустой:
  правила показывает его собственная схема, карточка добавляет только ход игры.
- **Раздача в личку — `renderDispatch({ title, rows, sent, onSent })`** (`dispatch.js`):
  когда человек должен знать что-то только своё. Одна строка на участника: имя, роль,
  готовый текст (plain text для мессенджера) и «Копировать»; отправленным ставится ✓.
  Экран ведущего, никогда не проектор. Используют «Скрытый профиль» (досье),
  «Рынок «лимонов»» (качество машины) и «Пивная игра» (недельная сводка).
- **Итоговая таблица — `renderLeaderboard({ rows: rankScores(...), unit })`**
  (`leaderboard.js` + `logic/leaderboard.js`): в играх, где каждый набирает очки
  («Слабое звено», «Кто возьмёт на себя», «Рынок «лимонов»», «Бар «Эль Фароль»»,
  «Угадай ⅔» — по победам, «Долларовый аукцион», «Дилемма заключённого», «Ультиматум»),
  на экране результатов и на проекторе (там — во всю ширину под результатом). Ничьи
  делят место. Намеренно нет в «Диктаторе» и «Общественном благе» — решения там
  анонимные, таблица с именами их раскрыла бы.
- **Сводка прошлого раунда** в многораундовых играх (`.round-recap` с
  `data-projector="body"`): только агрегаты, без имён, — чтобы зал видел, что
  получилось, и мог менять решение («Слабое звено», «Кто возьмёт на себя»,
  «Лимоны», «Угадай ⅔», «Общественное благо»).
- **`spoiler-card.js` + `SpoilerController`** — спрятанный текст с «Показать»
  и «Скопировать».
- **`chart-tip.js`** — `ChartTip.attachToPoint(svg, ns, cx, cy, content, hitRadius)`
  вешает на точку графика всплывающую подсказку по наведению: имя человека и его ответ. Добавляет
  свой увеличенный невидимый круг поверх маленькой видимой точки — 5–6px
  слишком мелкая мишень для мыши — и именно на него вешает обработчики.
  Сама подсказка живёт в `document.body` (общая на все графики), поэтому
  не требует доработки под shadow root.
- **`styles/shared-styles.js`** — весь `styles.css`, обёрнутый в Lit `css`
  через `unsafeCSS()`; каждый игровой компонент подключает его как
  `static styles = sharedStyles`. Специально весь файл целиком, а не
  вырезанное подмножество — см. обоснование в комментарии файла.

## Игроки

Кто играет — данные, а не код: панель «Игроки» слева вверху на главной (значок с числом играющих).
Имя добавляется полем и Enter; клик по имени — переименовать; галочка — «играет сегодня» (человек
остаётся в списке, но в игры не попадает); × — удалить; «Вставить списком» — имена по строкам или
через запятую (повторы пропускаются); «Удалить всех»; «Заполнить примером» — 14 человек для пробы.
Список хранится в `localStorage` (`retro.players.v1`) и переживает перезагрузку; при первом запуске
он пуст. Имена чистятся (пробелы, не длиннее 30 символов) и уникальны без учёта регистра — игры
различают людей по имени. Без хотя бы двух играющих игру не запустить: приложение говорит, что
делать, и ставит курсор в поле имени. Игры читают `state.participants`; проектор получает состав
и цвета аватаров вместе со снимком, так что на приветственном экране видна сегодняшняя команда.

## Экран для показа (проектор)

**Приветственный экран.** Пока игра не выбрана, окно проектора — живое приветствие в стиле главной
карты: те же пастельный фон и 3D-иконки (плавают и поворачиваются), световые шары, заголовок
появляется по словам с переливом, «Сегодня играют» — игроки выскакивают по одному, строка «в
программе» сама меняется на следующую игру, точки «ведущий выбирает игру». Это только CSS-анимация
(`src/projector/welcome.js`), масштабируется по `vmin`; при «уменьшить движение» стоит на месте.
Смена шага в игре тоже с плавным появлением.


Кнопка с иконкой монитора — рядом с × в игре и внизу карты — открывает второе окно
браузера, которое ведущий шарит в Zoom («Демонстрация экрана» → это окно), а основное
окно остаётся только у него: там поля ввода, тексты для групп, реплики ведущего.

Выглядит как само приложение: слева содержимое шага, справа — название игры и тропа с 3D-иконкой
и «Шаг N из M» (тот же `renderTrail`), карточки, аватары, цвет игры. На проекторе — то, что нужно
залу: задание или вопрос, **таймер на карте раундов** (кольцо вокруг иконки игры; последние 5 секунд красный, последние 3 экран пульсирует, по нулю вспышка и маленькая плашка) (кольцо с цифрами, идёт синхронно с таймером ведущего),
**правила и ход игры** на первом экране (карточка `renderRules`),
**составы групп и пар** (Фрейминг, Эффект владения, Ультиматум, Дилемма — с ролями, а после
раунда 1 в «Дилемме» и с выбором каждой пары; при трёх и больше группах — сетка: до четырёх в
ряд, больше — поровну в два ряда, число человек отдельной строкой),
**сводки прошлого раунда** и **табло** по ходу игры (аукцион — две верхние ставки и последние
шесть ставок, пивная игра — только номер недели и общие затраты), **данные по ходу заполнения** (человек за человеком,
пара за парой: карточка появляется с первым внесённым числом, счётчик «внесено N из M»; там, где
решение анонимное — «Диктатор», раунд 1, и «Общественное благо» — только суммы, отсортированные,
без имён), на результатах — главная цифра, график и итоговая таблица, на первом
экране — карточки «время / формат / направление» и правила. Картинка сама масштабируется под размер окна
и никогда не прокручивается.

Как устроено (подробно — в шапках файлов `src/projector/*`):

- Окна общаются через `window.postMessage` — второе окно открывается `window.open`, так что у
  каждого есть ссылка на другое; это работает и с `file://` (двойной клик по `dist/index.html`),
  где `BroadcastChannel` ненадёжен. Проектор раз в несколько секунд здоровается, поэтому связь
  восстанавливается сама после перезагрузки любого окна.
- **Наружу уходит только явно помеченное.** В шаблонах игр публичные элементы отмечены
  `data-projector="eyebrow|title|lede|body|reveal|chart"`; ничего без метки в проектор не попадает.
  `data-projector-text="…"` подменяет текст (например, вопрос вместо «Впишите ответы»),
  `data-no-projector` вырезает кусок внутри помеченного блока. Поля ввода, кнопки, тексты для
  групп (Фрейминг, Барнум), шаги и заметки на экране инструкции (они написаны для ведущего) —
  не помечены и не уходят. Проектор проверяет снимок (`normalizeSnapshot`) и чистит HTML.
- Составы передаются не разметкой, а данными: игра отдаёт `roster` (`{kind:'groups'|'pairs', …}`)
  через `new ProjectorController(this, id, { roster: (round) => … })`; проектор рисует их сам,
  а имена выводит текстом (экранируются), так что введённое как имя не станет разметкой.
- Внесённое передаётся так же данными: `entries: (round) => projectorEntries({ title, total, rows })`
  (`src/logic/projector-entries.js`). Пустые ячейки и люди без значений отбрасываются; у списка
  с `anonymous: true` нет имён вообще (их вырезает и получатель, `normalizeEntries`), а порядок задаёт
  значение, а не порядок ввода.
- Таймер читается с карточки таймера (`data-projector-timer` в `renderAnswerTimer`);
  `projectorLabel` задаёт подпись для зала, если основная написана для ведущего.
- Новая игра: добавить `new ProjectorController(this, '<id>')` в конструктор (после
  `ChartController`), `<retro-projector-button>` рядом с ×, и пометить публичные элементы шага.
- Всё, что уходит в личку («Раздача»), не помечается никогда; имена на проекторе допустимы только
  в составах (`roster`) и там, где игра открытая по сути (ставки аукциона, покупатели лотов,
  победитель раунда в «Угадай ⅔», итоговая таблица). `projector.spec.js` проверяет, что на
  экранах инструкции и ввода имён вне состава нет.

## Как добавить новую игру

1. Взять описание игры из `spec/game_platform_spec.md` (раздел 4.X); для игр
   второй партии полная фактура — в `docs/new-games/<id>.md`.
2. Создать `src/games/<id>.js` с классом `RetroGameXxx extends LitElement`
   — по образцу ближайшей по структуре существующей игры (одиночный ввод,
   пары или группы; см. `src/games/dictator.js` для полного разбора
   паттерна в шапке файла), импортируя то, что нужно, из `../state.js`
   (`state`, `avatarName`), `../persist.js` (`Persist`, `timeAgo`),
   `../report-export.js` (`ReportExport`), `../styles/shared-styles.js` (`sharedStyles`)
   и, если нужно, `../roles.js` / `../chart-tip.js` / `../toast.js`
   (`copyToClipboard`). Проход по раундам — `this.flow = new
   RoundFlowController(this, { titles })` (`advance`/`scrollTo`/`reset`/
   `roundClass`/`lock`), таймер ответа — `new AnswerTimerController(this,
   секунды)` (или `RoundTimers`, если таймер нужен на каждый раунд).
   Тексты инструкции/правил/контекста/фактов — в `src/content/<id>.json` (добавьте
   файл: тест `content.test.js` требует по одному на игру; новые `{плейсхолдеры}`
   допишите в его `KNOWN_PLACEHOLDERS`). На первом экране — `${renderRules(CONTENT.rules)}`
   перед баннером черновика. Если у людей есть личные очки — `renderLeaderboard`
   на результатах; если кому-то нужна личная информация — `renderDispatch`.
   Проектор: `ProjectorController` в конструкторе + `<retro-projector-button>` рядом с ×
   + `data-projector` на публичных элементах (см. «Экран для показа»).
   Поля ввода получают `aria-label` с именем участника — так проходит
   проверка `a11y.spec.js`. Подсчёт результатов — чистыми функциями в `../logic/`
   (`results.js` или свой `logic/<id>.js`) с юнит-тестом в `test/unit/`, а не
   внутри компонента. Текст под главной цифрой — функция в `reveal-copy.js`
   (и пара примеров в `SAMPLES` в `test/unit/reveal-copy.test.js`).
   Заканчивается
   `customElements.define('retro-game-xxx', RetroGameXxx)`.
3. В `src/state.js`: добавить игру в массив `GAMES` (`ready:true`, `structure`:
   `solo` / `pairs` / `groups` / `team`). Иконку взять свободную из `src/icons/`
   (PNG 300×300 → `bun run icons`) и её средний цвет вписать в `ICON_COLORS`
   в `src/map-render.js` — это акцентный цвет игры.
4. В `src/router.js`: импортировать новый файл игры (side-effect import)
   и добавить `id → 'retro-game-xxx'` в `GAME_TAGS`.
5. Добавить игру в `test/games.js` (один объект — как дойти до формы, чем
   её заполнить, как дойти до результатов; `restored(page)` — если черновик не
   в полях ввода) — остальные тестовые наборы подхватят её автоматически, а
   график результатов — строкой в `CHARTS` в `test/charts.spec.js`. Обычные `id`-селекторы работают
   как есть (Shadow DOM изолирует id по компонентам, Playwright пронизывает
   shadow root для `page.click`/`$eval`/`$$eval` автоматически) — см.
   игровых компонентов, где вместо `id` стоит `data-testid`.
6. `bun run verify` — собрать и прогнать весь набор (lint, сборка, E2E, юниты).

## Технические принципы (не менять без причины)

- Без бэкенда. `sessionStorage` используется только для черновиков одной
  игры на время вкладки (см. `persist.js`) — это не постоянное хранилище
  и не профиль пользователя, при закрытии вкладки всё пропадает.
- Один общий редактируемый список участников (`state.participants`) на
  уровне каркаса, а не внутри каждой игры.
- Единая драматургия игры: инструкция и правила для игроков (без названия
  эффекта и авторов) → [распределение ролей] → [раздача в личку] → сбор данных
  фасилитатором (сводка по раундам на проекторе) → результаты команды →
  [итоговая таблица] → контекст/история → экспорт в PNG.
- Единая дизайн-система: бумажный фон в линейку, гарнитура Fraunces для
  заголовков, IBM Plex Sans/Mono для остального, один акцентный цвет на
  категорию (когнитивные искажения — бирюзовый, экономика/теория игр —
  охра, соц. психология — слива).

## Тестирование

Подробности — в `test/README.md`. Коротко:

```bash
bun run verify        # lint + проверка необъявленных переменных + сборка + E2E + юниты
bun run test:unit     # только юниты и property-тесты (~1 с)
bun run test:a11y     # только доступность (axe на всех экранах)
bun run test:visual   # эталоны PNG-отчёта (см. test/README.md)
```

~1460 E2E-проверок (~12 минут: каждая из 21 игры целиком, карта, черновики,
экспорт PNG, графики, таймеры, доступность, проектор), ~810 юнит- и property-тестов.
Эталоны визуальных тестов (`test/visual/__snapshots__/darwin/`) пока записаны только
для первых 13 игр; для новых (и для «Дилеммы»/«Ультиматума», где в отчёт добавилась
итоговая таблица) их нужно перезаписать: `bun run test:visual:update`.
В CI (`.github/workflows/verify.yml`) три параллельных задания: `static`
(lint + юниты), `e2e` и `visual`.
