# retro — «5 минут общего развития»

Веб-платформа с мини-экспериментами (экономика/психология решений) для
командных встреч и ретро. Один сценарий на все игры: инструкция без
спойлеров → (распределение ролей, если нужно) → форма → результаты
команды → история эффекта → экспорт в PDF.

## Как работать с проектом

1. Правим только файлы в `src/` (и, если добавляем игру, кладём новый
   `src/games/<id>.js`).
2. Собираем: `bun run build` → обновляется `dist/index.html`.
3. Проверяем: `bun run test` (или `bun run verify`, чтобы собрать
   и прогнать тесты одной командой) — см. `test/README.md`.
   ⚠️ Именно `bun run test`, а не голый `bun test` — это свой
   test-runner Bun, у него другой формат тестов, см. `bunfig.toml`.
4. Отдаём пользователю только `dist/index.html` — это самодостаточный файл,
   открывается двойным кликом, без сервера и сборки на его стороне.

`bun install` сам ставит локальный git-хук `pre-push` (см. `scripts/`),
который перед каждым `git push` собирает проект и гоняет быстрый
smoke-набор (~15–20с, все 13 игр целиком, без остальных 9 наборов) —
чтобы явно сломанная игра не улетела на сервер до полного прогона в CI.
Полный набор (`bun run verify`) при этом всё равно гоняется в CI на
каждый push/PR (`.github/workflows/verify.yml`). Пропустить хук разово:
`git push --no-verify`.

`src/*.js` — настоящие ES-модули (см. `docs/modernization-plan.md`, Фаза 1),
поэтому `src/index.html` **больше нельзя** просто открыть двойным кликом —
браузеры блокируют `import` по `file://` (в отличие от классических
`<script src>`, на которых всё держалось раньше). Для живой проверки в
браузере во время разработки: `bun run dev` → http://localhost:5173.
Дополнительно, начиная с Фазы 4+, `home.js` и все игры импортируют `lit`
голым bare-специфайером (`import { LitElement } from 'lit'`) — браузер не
может зарезолвить такое сам ни при какой раздаче статики. Поэтому
`scripts/dev-server.js` не просто отдаёт `src/app.js` как есть: запрос на
`/app.js` он на лету прогоняет через `Bun.build()` (тот же бандлер, что и
`build.js`, только без минификации и с inline source map), которая
резолвит `lit` и весь остальной граф импортов в один валидный ES-модуль.
Остальное (`styles.css`, `index.html`, статика) по-прежнему отдаётся как
обычные файлы. `dist/index.html` эта проблема не касается — `build.js`
инлайнит весь собранный бандл как текст в один `<script type="module">`,
без отдельных файловых запросов.

## Общие паттерны (переиспользуются во всех играх)

Каждая игра — Lit-компонент (`LitElement`, `customElements.define('retro-game-<id>', ...)`)
с Shadow DOM: рендер декларативный (`html\`\`` шаблон + реактивные
`static properties`), а не императивная сборка `innerHTML` строк. Общие
модули ниже — то, что осталось переиспользуемым при таком подходе; часть
старого API (императивная генерация HTML + делегированные слушатели)
исчезла вместе с переходом на Lit — см. `docs/modernization-plan.md`
для истории и обоснования.

- **`roles.js`** — только чистые функции без DOM: `Roles.makePairs()` /
  `Roles.makeGroups()` случайно делят участников на пары или на 2 группы
  (при нечётном числе участников `makePairs()` формирует трио вместо
  наблюдателя — см. комментарий в файле), `Roles.swapInPairs()` /
  `Roles.swapInGroups()` меняют местами двух участников. Рендер карточек
  пар/групп и клик-для-обмена — в шаблоне каждого игрового компонента
  (реактивное состояние `selectedSwapName`), см. `src/games/ultimatum.js`.
- **`persist.js`** — `Persist.save/load/clear` пишут черновик игры в
  `sessionStorage` (только на вкладку, не навсегда) при каждом изменении
  ответа; `Persist.hasAny()` — предупреждение при закрытии вкладки с
  несохранённым прогрессом. `timeAgo(ts)` — отдельный экспорт для баннера
  восстановления, который каждый компонент рендерит декларативно из
  своего `this.draft` (загруженного в конструкторе через `Persist.load`).
- **`print.js`** — `Print.mount(id, data, root)` заполняет печатную шапку
  (название игры, тизер, дата и число участников) и, если передано поле
  `explanation`, футер «Что это было» под таблицей результатов; третий
  аргумент `root` — обычно `this.renderRoot` компонента (нужен, чтобы
  найти id внутри shadow root). `Print.run()` вызывает `window.print()`.
  Экран результатов печатается как есть — стили `@media print` в
  `styles.css` сами прячут навигацию и сжимают всё до одной страницы A4.
- **`chart-tip.js`** — `ChartTip.attachToPoint(svg, ns, cx, cy, content, hitRadius)`
  вешает на точку графика (Эффект якоря, Мудрость толпы, Игра диктатора)
  всплывающую подсказку по наведению: имя человека и его ответ. Добавляет
  свой увеличенный невидимый круг поверх маленькой видимой точки — 5–6px
  слишком мелкая мишень для мыши — и именно на него вешает обработчики.
  Сама подсказка живёт в `document.body` (общая на все графики), поэтому
  не требует доработки под shadow root.
- **`styles/shared-styles.js`** — весь `styles.css`, обёрнутый в Lit `css`
  через `unsafeCSS()`; каждый игровой компонент подключает его как
  `static styles = sharedStyles`. Специально весь файл целиком, а не
  вырезанное подмножество — см. обоснование в комментарии файла.

## Как добавить новую игру

1. Взять описание игры из `spec/game_platform_spec.md` (раздел 4.X).
2. Создать `src/games/<id>.js` с классом `RetroGameXxx extends LitElement`
   — по образцу ближайшей по структуре существующей игры (одиночный ввод,
   пары или группы; см. `src/games/dictator.js` для полного разбора
   паттерна в шапке файла), импортируя то, что нужно, из `../state.js`
   (`state`, `avatarName`), `../persist.js` (`Persist`, `timeAgo`),
   `../print.js` (`Print`), `../styles/shared-styles.js` (`sharedStyles`)
   и, если нужно, `../roles.js` / `../chart-tip.js` / `../toast.js`
   (`copyToClipboard`). Заканчивается
   `customElements.define('retro-game-xxx', RetroGameXxx)`.
3. В `src/state.js`: добавить игру в массив `GAMES` (`ready:true`).
4. В `src/router.js`: импортировать новый файл игры (side-effect import)
   и добавить `id → 'retro-game-xxx'` в `GAME_TAGS`.
5. Добавить игру в `test/games.js` (один объект — как дойти до формы, чем
   её заполнить, как дойти до результатов) — остальные тестовые наборы
   подхватят её автоматически. Обычные `id`-селекторы работают
   как есть (Shadow DOM изолирует id по компонентам, Playwright пронизывает
   shadow root для `page.click`/`$eval`/`$$eval` автоматически) — см.
   `docs/modernization-plan.md` за развилками, где вместо `id`
   стоит `data-testid`.
6. `bun run verify` — собрать и прогнать весь набор.

## Технические принципы (не менять без причины)

- Без бэкенда. `sessionStorage` используется только для черновиков одной
  игры на время вкладки (см. `persist.js`) — это не постоянное хранилище
  и не профиль пользователя, при закрытии вкладки всё пропадает.
- Один общий редактируемый список участников (`state.participants`) на
  уровне каркаса, а не внутри каждой игры.
- Единая драматургия игры: инструкция (без названия эффекта и авторов) →
  [распределение ролей] → сбор данных фасилитатором → результаты команды →
  контекст/история → экспорт в PDF.
- Единая дизайн-система: бумажный фон в линейку, гарнитура Fraunces для
  заголовков, IBM Plex Sans/Mono для остального, один акцентный цвет на
  категорию (когнитивные искажения — бирюзовый, экономика/теория игр —
  охра, соц. психология — слива).

## Статус игр

Все 13 игр реализованы и покрыты регрессионными тестами. См. таблицу в
`spec/game_platform_spec.md`, §2 для механики, формул и источников каждой.

## Тестирование

Подробности — в `test/README.md`. Коротко:

```bash
bun run verify
```

404 проверки (~3 минуты): полный прогон каждой из 13 игр, главный экран,
восстановление черновиков (включая гонку состояний при двойной
перезагрузке без явного восстановления), PDF-шапки, приватность общего
экрана, подсказки графиков и свои вопросы в играх-викторинах.
