# retro — «5 минут общего развития»

Веб-платформа с мини-экспериментами (экономика/психология решений) для
командных встреч и ретро. Один сценарий на все игры: инструкция без
спойлеров → (распределение ролей, если нужно) → форма → результаты
команды → история эффекта → экспорт в PDF.

## Структура проекта

```
retro/
├── README.md                 — этот файл
├── package.json               — bun-скрипты для сборки и тестов
├── bunfig.toml                 — конфиг Bun (держит `bun test` подальше
│                                  от test/, см. комментарий в файле)
├── build.js                   — собирает src/ в один файл dist/index.html
├── spec/
│   └── game_platform_spec.md     — спека всех 13 игр (механика, формулы,
│                                    источники) — источник правды при
│                                    добавлении новых игр
├── src/                        — исходники (редактируем ТОЛЬКО здесь)
│   ├── index.html               — dev-версия, подключает файлы через <script src>
│   ├── styles.css               — вся стилевая система
│   ├── app.js                   — состояние, список игр, главный экран, роутер
│   ├── roles.js                 — общий паттерн: разбивка на пары / 2 группы
│   ├── screen.js                — общий паттерн: переключение экранов игры,
│   │                                ссылка «← Все игры», прогресс-бар формы
│   ├── persist.js               — общий паттерн: черновики и восстановление
│   │                                после случайной перезагрузки
│   ├── print.js                 — общий паттерн: экспорт результатов в PDF
│   └── games/                   — 13 файлов, по одному на игру
├── test/                       — регрессионный набор (см. test/README.md)
│   ├── lib.js, games.js           — общая инфраструктура и описание всех игр
│   └── *.spec.js                  — smoke / home / persistence / pdf / swap / copy / trio

                                    открывает в Chrome/Safari, доп. файлы
                                    не нужны)
```

## Как работать с проектом

1. Правим только файлы в `src/` (и, если добавляем игру, кладём новый
   `src/games/<id>.js`).
2. Собираем: `bun run build` → обновляется `dist/index.html`.
3. Проверяем: `bun run test` (или `bun run verify`, чтобы собрать
   и прогнать тесты одной командой) — см. `test/README.md`.
   ⚠️ Именно `bun run test`, а не голый `bun test` — это свой
   test-runner Bun, у него другой формат тестов, см. `bunfig.toml`.
4. Отдаём пользователю только `dist/index.html` — это самодостаточный файл,
   открывается двойным кликом, без сервера и сборки на его стороне.

`src/index.html` тоже открывается напрямую (полезно для быстрой проверки
в браузере во время разработки) — браузеры разрешают классические
`<script src>`/`<link>` по `file://`, в отличие от ES-модулей и `fetch`.

## Общие паттерны (переиспользуются во всех играх)

- **`roles.js`** — `Roles.makePairs()` / `Roles.makeGroups()` случайно
  делят участников на пары или на 2 группы (при нечётном числе участников
  `makePairs()` формирует трио вместо наблюдателя — см. комментарий в файле),
  плюс `Roles.pairsHTML()` / `Roles.groupsHTML()` рисуют это на экране,
  `Roles.bindShuffle()` вешает кнопку «🎲 Перемешать», `Roles.bindPairSwap()` /
  `Roles.bindGroupSwap()` — точечный обмен местами по клику на двух участниках.
- **`screen.js`** — `Screen.goTo(screenIdx)` переключает `.screen`/`.dot`
  и прокручивает наверх (было продублировано в каждой из 13 игр один в один);
  `Screen.wireBackHome(gameId)` вешает на «← Все игры» очистку черновика и
  возврат на главный экран; `Screen.updateProgress(idSuffix, filled, total,
btnId, minRequired)` обновляет счётчик «Заполнено: N из M», прогресс-бар
  и disabled-состояние кнопки — тоже единая точка для того, что раньше было
  копией в каждой игре.
- **`persist.js`** — `Persist.save/load/clear` пишут черновик игры в
  `sessionStorage` (только на вкладку, не навсегда) при каждом изменении
  ответа. `Persist.offerRestore(gameId, mountId, validate, onRestore)` —
  одна функция вместо ручной сборки «загрузить черновик → проверить форму →
  показать баннер»: `validate(payload)` решает, годится ли черновик,
  `onRestore(payload)` получает его и сам решает, как восстановить состояние
  игры и куда перейти (формы у игр разные: `{data}`, `{entries}`,
  `{assignment, entries}`, `{groups, entries}`). Все 13 игр используют флаг
  `hydrated`, чтобы не перезаписать черновик пустыми данными во время самой
  первой отрисовки экрана — см. комментарий в начале `persist.js`, если
  добавляете новую игру по этому паттерну.
- **`print.js`** — `Print.mount()` заполняет скрытую на экране печатную
  шапку (название игры, тизер, дата и число участников) и, если передано
  поле `explanation`, футер «Что это было» под таблицей результатов — прямо
  перед переходом на экран результатов; `Print.run()` вызывает
  `window.print()`. Экран результатов печатается как есть — стили
  `@media print` в `styles.css` сами прячут навигацию и сжимают всё до
  одной страницы A4.
- **`chart-tip.js`** — `ChartTip.attachToPoint(svg, ns, cx, cy, content, hitRadius)`
  вешает на точку графика (Эффект якоря, Мудрость толпы, Игра диктатора)
  всплывающую подсказку по наведению: имя человека и его ответ. Добавляет
  свой увеличенный невидимый круг поверх маленькой видимой точки — 5–6px
  слишком мелкая мишень для мыши — и именно на него вешает обработчики.

## Как добавить новую игру

1. Взять описание игры из `spec/game_platform_spec.md` (раздел 4.X).
2. Создать `src/games/<id>.js` с функцией `renderXxxGame()` — по образцу
   ближайшей по структуре существующей игры (одиночный ввод, пары или
   группы) и подключить `roles.js`/`screen.js`/`persist.js`/`print.js` как
   описано выше.
3. В `src/app.js`:
   - в массиве `GAMES` поставить `ready:true` у нужной игры;
   - в `openGame(id)` добавить вызов новой функции рендера.
4. Добавить игру в `test/games.js` (один объект — как дойти до формы, чем
   её заполнить, как дойти до результатов) — остальные тестовые наборы
   подхватят её автоматически.
5. `bun run verify` — собрать и прогнать весь набор.

## Технические принципы (не менять без причины)

- Без бэкенда. `sessionStorage` используется только для черновиков одной
  игры на время вкладки (см. `persist.js`) — это не постоянное хранилище
  и не профиль пользователя, при закрытии вкладки всё пропадает.
- Один общий редактируемый список участников (`state.participants`) на
  уровне каркаса, а не внутри каждой игры.
- Единая драматургия игры: инструкция (без названия эффекта и авторов) →
  [распределение ролей] → сбор данных фасилитатором → результаты команды →
  контекст/история → экспорт в PDF.
- Единая дизайн-система: бумажный фон в линейку, гарнитура Fraunces для
  заголовков, IBM Plex Sans/Mono для остального, один акцентный цвет на
  категорию (когнитивные искажения — бирюзовый, экономика/теория игр —
  охра, соц. психология — слива).

## Статус игр

Все 13 игр реализованы и покрыты регрессионными тестами. См. таблицу в
`spec/game_platform_spec.md`, §2 для механики, формул и источников каждой.

## Тестирование

Подробности — в `test/README.md`. Коротко:

```bash
bun run verify
```

256 проверок (~2 минуты): полный прогон каждой из 13 игр, главный экран,
восстановление черновиков (включая гонку состояний при двойной
перезагрузке без явного восстановления) и PDF-шапки.
