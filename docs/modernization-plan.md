# План модернизации: Bun bundler + ESM, Web Components (Lit), CSS Modules

Финализировано. Решения по развилкам (2026-09-12):

1. **Shadow DOM** (нативный Lit, `css\`\`` на компонент) — не light DOM.
2. **Тесты мигрируют на `data-testid`** — CSS Modules хэширует классы
   свободно, тестовые селекторы больше не зависят от имён классов.
3. **Инкрементальный выкат** с пилотной игрой (`dictator`) — остальные
   12 по группам с прогоном тестов после каждой.
4. Дополнительно: **Biome** (линт+форматирование) и **`bun test`** для
   чистой логики (`Roles.makePairs`/`makeGroups`/`swapIn*` и т.п.) в
   дополнение к Playwright. TypeScript — вне текущего объёма.

Важное следствие (см. «Ключевой факт» ниже): переход общих модулей на
`export`/`import` **не может** быть постепенным по одному файлу — в
классическом (не-ESM) скрипте `export` — синтаксическая ошибка, а раз
один файл становится модулем, все 12 остальных, ссылавшихся на его
глобальные имена, должны получить `import` в тот же момент. Поэтому
«Фаза 1» ниже — один атомарный коммит на все 18 файлов (`src/*.js` +
все игры), не по одному файлу. Инкрементальность (по пилоту, дальше по
играм) начинается только в Фазе 2 — где встаёт вопрос компонентной
модели (Lit/Shadow DOM/CSS Modules), а не модульной системы.

## Зачем этот документ

Текущая архитектура (см. README) — 13 игр + 5 общих паттернов
(`roles.js`, `screen.js`, `persist.js`, `print.js`, `chart-tip.js`) +
`app.js`, все как классические (не-ESM) скрипты, делящие один глобальный
scope, конкатенируемые `build.js` в единый `dist/index.html`. Это
осознанный выбор ради простоты и нулевых зависимостей — но не
использует ни бандлер, ни компонентную модель, ни изоляцию стилей.

Цель модернизации — трижды заявленная (bundler+ESM, Web Components/Lit,
CSS Modules) плюс общее «современные практики» — при этом **не потеряв**:
- единый самодостаточный `dist/index.html` (двойной клик, без сервера);
- всё поведение 404 Playwright-тестов (см. `test/README.md`);
- `sessionStorage`-черновики, приватность общего экрана (блюр полей),
  PDF-экспорт, трио-фолбэк при нечётном числе участников и т.д.

## Текущая архитектура (снимок на момент анализа)

| Файл/группа | Строк | Суть |
|---|---|---|

| `src/roles.js` | 270 | Чистые функции (`makePairs`/`makeGroups`, шаффл, свап) + HTML-хелперы + делегированные обработчики свапа |
| `src/screen.js` | 78 | `Screen.goTo/wireBackHome/updateProgress` — общая навигация по `.screen`/`.dot` |
| `src/persist.js` | 125 | `Persist.save/load/clear/offerRestore` — черновики в `sessionStorage`, баннер восстановления |
| `src/print.js` | 127 | `Print.mount/run` — печатная шапка/футер, `window.print()` |
| `src/chart-tip.js` | 85 | Подсказка при наведении на точку SVG-графика |
| `src/app.js` | 353 | `state`, `CATEGORY`, `GAMES`, главный экран, роутер `GAME_RENDERERS`, делегированный обработчик приватности toggle-кнопок |
| `src/styles.css` | 1227 | Один файл: токены (`:root`), типографика, все игровые компоненты, `@media print` |
| `test/*.spec.js` | 404 проверки | Playwright, реальный headless-браузер поверх **собранного** `dist/index.html`, селекторы по id/классам/`data-*`/тексту |

Ключевой факт (проверено экспериментально): всё это работает только
потому, что файлы делят один top-level scope (либо через конкатенацию в
`build.js`, либо через несколько классических, не-`type=module`,
`<script src>` в dev `src/index.html`). Настоящий ES-модуль (`import
"./file.js"`) **не** протаскивает `const X = ...` между файлами — Bun
(и любой ESM-бандлер) обернёт каждый файл в свой scope. Значит переход
на реальный `import`/`export` — это не косметика, а необходимость
явно проэкспортировать `Screen`, `Persist`, `Roles`, `Print`,
`ChartTip`, `state`, `avatarName`, `CATEGORY`, `showToast` и т.д. и
явно проимпортировать их в каждом из 13 файлов игр.

## Целевая архитектура (предлагается)

- **ESM everywhere.** Каждый файл — модуль с явными `export`/`import`.
  Игры оформляются как кастомные элементы (`<retro-game-anchoring>` и
  т.п.), общие паттерны — как небольшие ES-модули и/или Lit reactive
  controllers (переиспользуемая логика без собственного DOM):
  `RolesController`, `PersistController`, `ScreenController`.
- **Web Components на Lit** вместо строковых `innerHTML`-шаблонов:
  декларативные `render()` с Lit `html\`\`` и реактивными
  `@property`/`@state`, `@click=${...}` вместо инлайновых `onclick="..."`
  строк в разметке.
- **CSS Modules** (или Lit `css\`\`` — см. развилку №1) для новых/
  переносимых стилей вместо роста одного плоского `styles.css`.
- **Bun как бандлер**: `build.js` вызывает `Bun.build()` на реальном
  графе зависимостей (единая точка входа `src/main.ts`/`main.js`,
  импортирующая `<retro-app>`), результат — один JS-бандл + один
  CSS-бандл, которые build.js по-прежнему инлайнит в единый
  `dist/index.html` (эта часть шаблона в целом остаётся).
- **Lit** тянется как обычная `devDependency`/`dependency` через
  `bun install` и попадает внутрь бандла (никакого CDN/рантайм-запроса
  у пользователя — тот же принцип «один файл, без сети»).
- Поведение (черновики, приватность, PDF, трио) **не меняется** —
  меняется только то, *как* оно реализовано технически.

## Последствия принятых решений

### Shadow DOM (не light DOM)
Значит: (а) `styles.css` придётся разложить на общие design-token'ы
(CSS custom properties на `:root` документа — они пересекают границу
shadow root и продолжат работать) + собственные `css\`\`` блоки в
каждом компоненте для всего остального (типографика, `.wrap`,
специфичные для игры стили); (б) печать/PDF (`window.print()`,
`@media print`) нужно будет явно спроектировать заново — либо через
`::part()`/slotted-контент, либо печатный узел рендерится в light DOM
через `<slot>`, чтобы `@media print` в документ-уровневом стиле мог его
видеть — это прорабатывается на пилоте (Фаза 2) до переноса остальных
12 игр; (в) весь `document.getElementById(...)` в общих модулях и играх
переписывается на `this.renderRoot.querySelector(...)` внутри классов
Lit-компонентов.

### Тесты на `data-testid`
Все ~404 проверки, которые сейчас цепляются за CSS-классы/id
(`.entry-row`, `#entry-body`, `.draft-restore`, `button[data-val="C"]`
и т.п.), получают устойчивые `data-testid="..."` атрибуты — независимые
от того, как хэширует классы CSS Modules. Именно поэтому Playwright
должен уметь пронизывать Shadow DOM: он это делает автоматически для
CSS-селекторов (в т.ч. `[data-testid=...]`) на открытых (`open`) shadow
root — все Lit-компоненты создаются с `shadowRootOptions: { mode:
'open' }` (значение по умолчанию в Lit), это не отдельная задача.
Правка теста и правка компонента идут в одном коммите на пилоте —
дальше это шаблон для остальных 12 игр.

### Инкрементальный выкат, пилот — `dictator`
Общие модули переходят на ESM атомарно (Фаза 1, все 18 файлов сразу —
см. «Ключевой факт» выше), а вот перевод конкретной игры в Lit/Shadow
DOM/CSS Modules/data-testid идёт по одной игре за раз, начиная с
`dictator.js` (средняя сложность: два раунда, график, печать, черновик,
без ролей/пар — при этом достаточно богат, чтобы вскрыть все подводные
камни печати и черновиков до переноса остальных 12).

### Biome + `bun test`
Biome — линт и форматирование одним инструментом, конфиг
`biome.json`, скрипты `bun run lint` / `bun run format`. `bun test`
покрывает чистую логику без DOM: `Roles.shuffle/makePairs/makeGroups/
swapInPairs/swapInGroups` в первую очередь (лежат в `test/unit/*.test.js`,
`bunfig.toml` указывает `[test] root` именно туда, чтобы не
пересекаться с Playwright-наборами в `test/*.spec.js`).

## Фазы

- **Фаза 0 — Подготовка.** `git init` + бейзлайн-коммит текущего
  зелёного состояния (404/404). `bun add lit`, `bun add -d
  @biomejs/biome`. `test/unit/` + `bunfig.toml` под `bun test`.
- **Фаза 1 — Общие модули → ESM (атомарно, все 18 файлов).**
  `roles.js`, `screen.js`, `persist.js`, `print.js`, `chart-tip.js`,
  `app.js` (state/router) и все 13 игр получают явные
  `export`/`import`. **Рендеринг и DOM остаются прежними** — это ещё
  не Lit и не Shadow DOM, только модульная система и способ сборки
  (`build.js` переходит на `Bun.build()` вместо ручной конкатенации).
  Полный набор тестов должен остаться зелёным без единой правки в
  тестах на этом шаге — поведение и разметка не меняются. Первые
  `bun test`-юниты на `Roles` (теперь с реальным `export`) пишутся
  здесь же.
- **Фаза 2 — Пилотная игра (`dictator`).** Переписывается как
  `<retro-game-dictator>` на Lit с Shadow DOM и `css\`\`` стилями;
  печать/PDF решается здесь впервые (самая рискованная часть); её
  тесты (`test:...`, плюс общие `smoke`/`persistence`/`pdf`/`privacy`/
  `chart-tip`, которые её тоже проверяют) переводятся на
  `data-testid`. Полный прогон `bun run test` — обязательный чекпоинт
  перед продолжением.
- **Фаза 3 — Остальные 12 игр.** Тем же шаблоном, группами (по
  категориям: cognitive/econ/social), с прогоном соответствующего
  `test:*`-поднабора после каждой и полного набора в конце каждой
  группы.
- **Фаза 4 — Финализация.** Домашний экран (`app.js` → `<retro-app>`/
  `<retro-home>`) и общие паттерны переводятся на Lit-контроллеры;
  `styles.css` — на общие токены + `css\`\`` по компонентам; удаление
  отживших паттернов (`window.xGoTo`, инлайновые `onclick`).
- **Фаза 5 — Документация и CI.** Обновление `README.md`/
  `test/README.md`, `bun run lint`/`bun run format` в CI.

## Риски и как их держим под контролем

- **Единственная сеть безопасности — 404 Playwright-теста.** Каждая
  фаза заканчивается зелёным прогоном `bun run test` (или релевантного
  поднабора) перед коммитом.
- **git обязателен** для этого объёма правок — без него нет
  возможности откатить фазу, если что-то пошло не так на середине.
- **PDF/печать — самая хрупкая часть** при выборе Shadow DOM (развилка
  №1) — стоит явно протестировать печать после первой же игры с новым
  стеком, а не откладывать на конец.
- **Инкрементальный выкат** (развилка №3а) — самый низкий риск: в
  любой момент есть последний зелёный чекпоинт, откуда можно
  продолжить или отступить.
